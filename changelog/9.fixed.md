`ldap.managed` now correctly handles `replace:` directives against OpenLDAP `cn=config` attributes (e.g. `olcSyncRepl`). User-supplied attribute names are matched case-insensitively against the server's canonical case, an opportunistic `{N}` X-ORDERED prefix normalization makes the state idempotent on those attributes, and the backend emits an atomic `MOD_REPLACE` for `replace:`-directed attributes instead of routing through an add/delete diff. References saltstack/salt#54444, saltstack/salt#33786, saltstack/salt#68626.
